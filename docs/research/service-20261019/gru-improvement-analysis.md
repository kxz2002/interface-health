原4窗/hidden32/50轮为固定基线，两个候选分别只改变历史长度或隐藏维度。seed为1、2、42，其他设置及评分保持不变。原配置、checkpoint和输出未覆盖。

九组外层实验和独立Normal验证均通过递归`check_run`。`scripts/audit_gru_candidates.py`另检查声明文件大小/SHA256、fit/calibration/test/main精确ID、版本与prepared父绑定一致，并以SQLite只读方式核对真实MLflow。共450个epoch的`fit_loss`与声明`training_history`完全一致。逐轮曲线、逐seed指标、q99混淆矩阵及Normal逐服务误差见[审计摘要](gru-improvement-audit.json)。远端复核命令：

```bash
~/miniconda3/envs/interface/bin/python scripts/audit_gru_candidates.py \
  --root ~/Code/Repos/interface-health/outputs/service
```

## Normal验证与训练过程

仅outer fit四个完整Normal Case参与内部验证：前三个重新拟合归一化、日志模板及统计、可用性先验，最新完整Case验证。实际拟合7291窗、验证2857窗。外层校准集未用于候选选择。

|模型|Normal总损失|数值误差|可用性误差|
|---|---:|---:|---:|
|原GRU|0.797593±0.048527|0.648606|0.148987|
|8窗|0.793066±0.039945|0.646459|0.146607|
|hidden64|0.805426±0.018363|0.652552|0.152875|

8窗Normal总损失只在seed1降低，seed2/42上升。hidden64将外层末轮fit loss从约0.345降至0.323，但完整Normal验证损失略升。扩大拟合能力没有带来相应的跨Case泛化收益；不能仅据此认定唯一原因是过拟合。

原模型Normal验证误差约81%来自数值部分。逐服务数值误差最高为basic（3.332）和travel（2.328），其余大多低于1。这不说明相应故障的检出能力。下一步仅以内部Normal数据比较历史持久性预测及逐特征误差，检验因果残差预测是否有依据，再决定第三个候选。
