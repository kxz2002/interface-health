# 当前研究目标：已与用户对齐的版本

更新：2026-10-19。本说明供后续 agent 读取，覆盖早期研究报告中过高的新颖性门槛，但不覆盖真实数据事实或实验结果。

## 要做什么

硕士论文总体目标是 Service–Endpoint 双层异常感知。同一受控实验同时获得内部运行状态和外部业务响应，为两层异常识别及后续关联分析提供基础。

- **研究内容一：** 输入 Service 运行时 Metrics、Logs、Traces 等特征，判断某一 Service 在固定时间窗内正常还是异常。标准输出为 `(case_id, service, window, anomaly_score, predicted_binary)`；Service×15s 可作为当前起点，窗口协议仍需冻结。
- **研究内容二：** Endpoint×时间窗异常识别，沿用已有研究基础，后续独立改进。
- 两个模型独立输出；后续利用实际 Service–Operation–Endpoint 关系解释差异和联系。不能要求 Endpoint 只有在 Service 报警后才能报警，也不预先声称跨层融合会提高性能。

主任务不是缺失观测三分类、根因检索、实例恢复检测或 Operation 路径诊断。这些可以是辅助模块/消融/解释，不应代替主任务。

## 创新的适当尺度

目标是可信、可复现的硕士论文，不是先证明顶会级原创才准写模型。可以在成熟机器学习、LSTM/GRU、Transformer、GNN、日志编码等方法上做适合场景的适度改进。模型组合本身不是性能证据；合理动机、明确差异、公平增益、必要消融和限制说明足以作为逐步推进的依据。

不保证一定超过全部基线，不将尚未试验的方案写成已验证贡献。允许先跑现成 ML 基线和一个轻量时序模型，再决定改进方向。统计/规则基线仍应保留作为下限/强参照，但不能用“部分故障统计即可检出”推导出“没有必要开发 Service 模型”。

## 二分类任务、训练方式与标签是三件事

1. 二分类描述预测输出，不自动意味着必须监督训练。现有 Normal-only 协议在用户明确变更前继续有效；单类/无监督模型可输出分数，经独立校准集阈值形成二分类。
2. 新批 17 个正式 Case（6 Normal、11 故障）已完成采集验收；**采集验收通过不等于每个 Service×Window 都已有独立二分类真值**。
3. metadata 中注入对象和时间用于构造评价范围/候选标签，不是所有服务的实际状态。不得把所有注入窗口一律标异常，也不得把非目标 Service 或恢复阶段一律标正常。
4. 每个参与主评价的窗口需记录 `label`、`label_source`、适用范围和证据。未知窗口排除出对应训练/评价，不补成正常，也不必新增第三个预测类别。
5. 根据检测输入本身阈值生成的标签属于同源弱标签，不能用来证明该输入检测真实异常的能力。弱标签、注入目标代理任务和独立验证窗口应分开报告。

不要求先把系统中每个服务的每个窗口全部标完才能开始有限原型；但不能在不可靠标签上报告“全服务真实二分类准确率”。

## 实验底线

- 明确冻结数据版本、allowlist、实例/Counter 语义、缺失处理和可用时间，禁止注入时间、Case 名、故障类型、phase 等标签字段进入特征。
- Normal 按独立 Case 划分训练/校准/测试，时序上下文不跨划分边界；异常 Case 留作测试，阈值不得用测试故障挑选。
- z-score/max/L2、Isolation Forest、OCSVM 等和候选模型尽可能同输入、同样本、同划分；额外模态带来的改善与模型机制改善分开验证。
- 报告窗口二分类、事件检测及分故障结果；目标 Service 检索只是辅助代理任务，不替代主任务。避免只给混合窗口总体指标。
- 最终效果一般也可据实报告、缩小改进主张；不得为得到理想结果换标签、隐藏失败 Case 或事后选阈值。
