## 已确认决策

- 保持 Normal-only、完整 Case 隔离，以及现有 4 Normal 拟合 + 1 Normal 独立校准 + 1 Normal 测试划分。
- 主评价负类仅取独立 Normal 测试 Case `Normal_20261018T153211Z_e448a74ed7104ebd` 中通过准入的正常参考窗口。当前标签表为 2,975 行；模型输入有效性掩码之后的数量另报。
- Fault Case 的注入前参考窗口不进入主评价负类，也不用于拟合、校准或模型选择。已有负类标签可保留，通过独立评价掩码排除；不需要为了改变评价范围而把这些已知参考标签改为 Unknown。
- 正类考虑纳入已探查的网络规则参与对象与 KILL 严格证据窗口。当前 479 = 原 A 版 194 + 网络参与对象候选 273 + KILL 双重就绪缺失候选 12。479 是待新版规则验收的候选数量，不是已发布标签数；逐对象边界和质量条件仍须核验。路由单证据上界 480 不作为本次严格方案目标。
- 真正 Unknown 继续从对应分类指标中排除，不填 0、不作为第三个模型类别；所有方法共享事先固定的评价样本及输入质量规则。
- 在尚未应用输入质量掩码的候选口径下，负类∶正类 = 2,975∶479 ≈ 6.21∶1，正类约 13.87%。这是本评价范围的组成，不能宣称是全部 Service 窗口的真实异常率。
- 用户后续自行补采 Case，以扩大正类和服务/事件覆盖。本轮不执行补采。新增 Case 必须有显式清单、来源与证据绑定、输入质量验收及新的数据/标签/评价版本；不通过目录 glob 自动接入。新增 Fault 仍仅测试。

评价范围应在查看模型测试成绩前固定。论文说明其测量的是未见 Normal 运行与已声明受控暴露窗口的区分能力，并公布排除的故障前窗口、Unknown、有效输入覆盖、每 Case 结果及独立事件数。6.21∶1 不作为性能成立或审稿接受的保证。
